## 1. What Sidereal is

A personal, single-user, agentic news reader for one owner (cloud network / security architect).
Every 4 hours (00, 04, 08, 12, 16, 20 Europe/London) it:

1. fetches ~21 sources (RSS/Atom, the MSRC update guide, CISA KEV JSON, HN Algolia search),
2. normalises items to plain text and groups them into **stories** (one event, ≥ 1 items),
3. drops obvious noise with a keyword **prefilter**, asks a local LLM to **triage** the rest in
   batches (relevance 0–3),
4. fetches article text for kept stories (**enrichment**) and asks the LLM to **assess** each one
   (rubric numbers + summary + "why it matters"),
5. computes a **score and bucket in code** (TOP / Relevant / On the side / drop): the model never
   decides placement,
6. writes a **day digest** (and on Sundays/Mondays a **week digest**), sends **notifications** for
   new TOP stories, prunes old data.

A FastAPI app serves a React UI: **Gazette** (rolling 24 h), **Daily** (per day, labelled
`Sunday - 12.07.2026`), **Week**, **Search**, **Runs**, **Sources**, **Settings**, with feedback
(votes, read, hide, mutes) that nudges future scores.

Focus areas (seeded from `config/defaults/focus.toml`, tiers in brackets): `azure-networking`
(primary), `network-architecture`, `entra-identity`, `ms-security`, `network-security`,
`security-news`, `industry` (see the file for tiers, descriptions and keywords).

LLM: local Ollama at `http://192.168.221.1:11434`; default model `qwen3.8:27b` for triage,
assess and digests (thinking off). The GPU is shared with the pi coding agent, hence the "gate"
(§4.1).

Stack: Python 3.13, FastAPI, httpx, pydantic v2, feedparser, trafilatura, argon2-cffi, SQLite
(WAL, FTS5); React 18 + Vite 5 + TypeScript + React Query + React Router 6. ~11.7k lines of
Python in `src/`. No Node at runtime: `web/dist` is served by the Python app.

## 3. Runtime architecture

Three processes, all systemd **user** units (`deploy/`), never running as root:

| Unit | What | Notes |
|------|------|-------|
| `sidereal-web.service` | `sidereal serve --host 127.0.0.1 --port 8470` | long-running uvicorn, 1 worker |
| `sidereal-run.timer` → `sidereal-run.service` | `sidereal run --trigger timer` | `OnCalendar=*-*-* 00,04,08,12,16,20:00:00 Europe/London`, `Persistent=true`, `TimeoutStartSec=3h` |
| `sidereal-run-manual.service` | `sidereal run --trigger manual` | started by `POST /api/runs` via `systemctl --user start --no-block` |
| `sidereal-backup.timer` → `.service` | `sidereal backup` | 03:30 London, keeps 14 |

State and config (XDG):

- State dir `~/.local/share/sidereal/` (`[paths] state_dir` / `SIDEREAL_PATHS__STATE_DIR`):
  `sidereal.db` (SQLite WAL), `run.lock`, `backups/sidereal-YYYYMMDD-HHMM.db` (UTC).
- Config `~/.config/sidereal/sidereal.toml` (optional; `SIDEREAL_CONFIG` overrides the path) and
  `~/.config/sidereal/env` (secrets, mode 600, loaded by the units with `EnvironmentFile=-`).
- Code runs from the editable install in `~/Projects/Sidereal/.venv`; seeds, prompts and
  `web/dist` are found relative to the checkout (`paths.project_root()`).

Communication: the run process and the web process share only the SQLite DB and the lock file.
The web app never runs the pipeline itself; "Run now" asks systemd. Hardening on the units:
`NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=strict`, `ProtectHome=read-only`,
`ReadWritePaths=%h/.local/share/sidereal`, `RestrictAddressFamilies`, `PYTHONDONTWRITEBYTECODE=1`.

## 4. The run pipeline, step by step

Entry: `sidereal run` → `commands.py` (migrate, take `RunLock`, build `Fetcher` + `OllamaClient`,
optional gate) → `pipeline/runner.run_once(settings, conn, *, fetcher, ollama, trigger, now, gate,
only_source, max_assess, clock) -> RunRow`. `run_once` applies `overrides.effective_settings`
first, so Settings-page overrides apply to the whole run.

Order inside `run_once` (see `src/sidereal/pipeline/runner.py`):

```
recover_stale → start_run (backfill 72 h if no ok run yet) → gate.wait → Deadline(max_run_minutes)
→ ingest.ingest → placement.refresh(joined) → placement.reopen(joined)
→ assess_step.run_assess (prefilter → triage → enrich → assess → place)
→ digest_step.update_days (touched days + last 3 local days)
→ week_step.update_weeks (previous ISO week; + current week on Sundays)
→ notify.dispatch (if channels configured) → retention.apply_retention
→ unload models (only if the LLM was used) → finish_run(status, stats)
```

Story states: `new` → `filtered` (prefilter) | `triaged_out` (triage) | `assessed` |
`assess_failed`. `new` stories not reached (caps, deadline, LLM down) simply wait for the next run.

### 4.1 Lock, recovery, gate, deadline

- **Lock** (`pipeline/lock.py`): `fcntl.flock` on `$STATE/run.lock`, non-blocking. A second run
  gets `RunLocked`, records a `skipped` run row and exits 0. `rescore` takes the same lock.
  `is_held()` probes read-only (used by `POST /api/runs` → 409). Stale files are harmless.
- **Recovery**: `runs_repo.recover_stale` turns leftover `running` rows into `failed`/`interrupted`.
- **Gate** (`llm/gate.py`): waits politely for the shared GPU. Busy if any pi-bridge run dir
  (`~/.pi-bridge/runs/rN/state`) says `running`, else probes the triage model with a 1-token
  generate and treats `(total_ms - load_ms) > probe_busy_seconds` (20 s) as busy. Polls every
  60 s up to 90 min, then proceeds anyway. `--no-gate` skips it.
- **Deadline** (`pipeline/common.Deadline`): `max_run_minutes` (45) starts *after* the gate;
  checked before every LLM call and enrichment; hitting it makes the run `partial`.

### 4.2 Ingest: fetch, normalise, dedupe, store

Files: `pipeline/ingest.py`, `pipeline/dedupe.py`, `sources/*.py`, `net/fetch.py`, `net/guard.py`.

- **Adapters** (`sources/`): registered by `kind` (`rss`, `msrc`, `cisa_kev`, `hn_algolia`).
  Interface: `fetch(source, fetcher, now, *, max_age_hours) -> FetchResult(items, etag,
  last_modified, not_modified, entry_count)`. RSS/MSRC parse with feedparser (bytes only), apply
  `include`/`exclude` regex options, age cap, `max_items`. MSRC filters by product regex *before*
  capping. KEV returns entries by `dateAdded` in the window. HN runs one Algolia query per
  `options.queries` with `typoTolerance=false` and `points>=min_points`. An HTML error page or
  bozo feed → `SourceBroken`.
- **Fetcher** (`net/fetch.py`): the only internet HTTP client. Guard check on every hop
  (redirects followed manually, ≤ 5), size cap (stream-capped, decoded bytes), timeouts, UA
  `Sidereal/<version> (+personal news reader)`, conditional GET, per-host concurrency 2, retries
  only on connect errors / 502–504 (2 s, 6 s), one numeric `Retry-After` ≤ 60 s on 429.
  `post_json` exists for Discord (no redirects, 5xx not retried).
- **Guard** (`net/guard.py`): `UrlGuard.check(url, allow_hosts=None)` resolves DNS and refuses
  non-http(s), userinfo, ports other than 80/443, private/loopback/link-local/reserved addresses,
  numeric host tricks. `allow_hosts=[]` allows nothing.
- **fetch_all**: all enabled sources concurrently (6); any exception is that source's error
  (health recorded via `sources_repo.record_fetch_ok/_error/_broken`), never the run's.
- **normalize**: canonical URL (`urls.canonicalize`: tracking params removed, query sorted),
  `textclean.clean_title`, `textclean.excerpt` (HTML → plain text, ≤ 1500), `normalize_title`,
  CVE ids = adapter ids + ids found in title/excerpt (text ids only if ≤ 3).
- **Dedupe** (`dedupe.assign_stories`, pure): order duplicate (url/guid) → MSRC roll-up (≥ 5 MSRC
  items same UTC date → one closed story) → CVE match vs known stories (story ≤ 3 CVEs, lowest id)
  → title Jaccard ≥ 0.6 (≥ 4 tokens) vs known → same rules vs earlier batch groups → new story.
  Known = stories seen in the last 72 h (`dedupe_window_hours`).
- **store**: create story at its first stored item, `insert_item` (UNIQUE conflict → duplicate),
  `attach_item` (lead item, `last_seen_at`, CVE merge), KEV items set `flags.kev`/`kev_vendor`.
  A story's `day` = local day (`schedule.tz`) at first sight, never recomputed.

### 4.3 Prefilter and triage

Files: `pipeline/prefilter.py` (pure), `llm/triage.py`, orchestration in `pipeline/assess_step.py`.

- **Prefilter** per `new` story, in order: all sources muted → `muted_source`; muted keyword →
  `muted_keyword`; older than `max_age_hours` (96) → `too_old`; KEV vendor Microsoft →
  **always keep**; source weight ≥ 1.3 → always keep (`trusted_source`); a primary-tier keyword →
  always keep; else → triage. Drops become `filtered` with `filter_reason`. A hint score
  (Σ tier weight 3/2/1 × distinct keyword hits) orders triage.
- **Triage** (`triage.v1` prompt): stories in §7.2 order (oldest age band first, then hint), cut to
  `max_triage_per_run` (150), batches of 15. Model returns `[{id, relevance 0..3}]`. Missing ids
  re-queued once, then relevance 1. An invalid batch counts as all-missing. Relevance ≥ `keep_min`
  (2) is kept; else `triaged_out`. `LLMUnavailable` ends the step (run `partial`).
- **Assess queue** = always-keeps + earlier-triaged still-`new` stories ≥ keep_min + this run's
  keeps, ordered by `assess_order` (triage relevance desc, always-keeps count as 3, then §7.2
  order), capped at `max_assess_per_run` (40). The rest stay `new` for the next run.

### 4.4 Enrichment and assessment

Files: `pipeline/enrich.py`, `llm/assess.py`, `llm/prompts.py`, `pipeline/assess_step.py`.

- **Enrich** the lead item only, only if `content_status` is NULL, only for hosts in the source's
  `options.article_hosts` (empty → `skipped`, no request). trafilatura extracts text offline (in a
  thread), then `textclean.to_text`, ≤ 20000 chars, stored as `items.content_text` with
  `content_status` ok/blocked/failed/skipped. Deadline skips are not stored (retried).
- **Assess** (`assess.v1` prompt): rendered with focus areas and an `<untrusted_article>` block
  (title, sources, published, excerpt ≤ 1500, article text ≤ 6000). JSON-schema-constrained reply:
  `relevance/urgency/actionability/novelty` (strict int 0..3), `exploited_in_wild` (strict bool),
  `focus` (enum of enabled focus keys + `none`), `tags` ≤ 5, `summary` ≤ 600, `why` ≤ 300.
  Invalid → one retry → `LLMOutputInvalid` → story `assess_failed` (bucket side, no score).
  URLs are stripped from summary/why. Saved via `assessments_repo.save_assessment` with
  `raw_json` = the reply (the API reads `focus` from it). `exploited` → `flags.exploited`.

### 4.5 Scoring and placement

Files: `pipeline/scoring.py` (pure), `pipeline/placement.py`, view caps in `api/present.py`.

Score (0..100, `scoring.score_story`):

```
100 × (0.40·rel + 0.25·urg + 0.20·act + 0.15·nov) / 3
+ 10 × (max source weight − 1)
+ 12 if KEV  + 8 if exploited_in_wild  + 8 if CVSS ≥ 9 / 4 if ≥ 7
+ min(4 × (distinct sources − 1), 12)            corroboration
+ 5 if focus tier primary  − 5 if focus tier side
+ feedback boost clamped ±10
clamped to 0..100
```

Bucket (`bucket_for`): no score → side; relevance 0 → drop; ≥ 72 top, ≥ 48 relevant, ≥ 25 side,
else drop; then a low-weight rule demotes top → relevant when max source weight < 1.0 unless
relevance ≥ 2 and (≥ 2 sources or urgency 3). The **stored** bucket is uncapped. **Caps** are
applied per view by `scoring.place` (top_cap 8 → overflow to relevant, relevant_cap 30 → overflow
to side); the Gazette sorts by score × recency (1.0 under 6 h, linear to 0.8 at 24 h).
All numbers live in `[scoring]` and are overridable in the Settings UI.

- `placement.place_assessed` after assessment; `placement.refresh` re-places assessed stories
  that gained items this run (corroboration); `placement.reopen` sends `filtered`/`triaged_out`
  stories that gained items back to `new`; `placement.rescore` (CLI `sidereal rescore`) recomputes
  everything without the LLM.
- **Feedback boost** (`scoring.feedback_tables` / `feedback_boost`): votes build smoothed boosts
  per source and per topic (`focus:<key>`, `tag:<tag>`), `10 × (up − down)/(up + down + 5)`; a
  story gets the mean over its voted-on sources + mean over voted-on topics, clamped ±10. A vote
  changes scores only at the next run or `rescore`.

### 4.6 Day and week digests

- **Day** (`pipeline/digest_step.py`, `llm/digest.py`, `day_digest.v1`): the set = the day's
  placed TOP + Relevant (caps applied, hidden excluded). Written only if non-empty and different
  from the stored `story_ids`. Reply `{overview ≤ 1200 chars, headline ≤ 160}`, URLs stripped.
  Checked days: those touched this run + the last 3 local days.
- **Week** (`pipeline/week_step.py`, `llm/week_digest.py`, `week_digest.v1`, `weeks.py`): ISO
  week of the local date (`YYYY-Www`). Every run checks the previous week; Sunday runs also the
  current week. Set = per-day placed TOP then Relevant, hidden removed, ≤ 25. Overview ≤ 2400
  chars. Exported as Markdown at `/api/weeks/{week}/export.md` (all stored text escaped).
- Invalid reply or empty field → `failed`, deadline → `skipped`; both make the run `partial`
  and are retried next run.

### 4.7 Notifications

Files: `notify/dispatcher.py`, `notify/discord.py`, `notify/email.py`, `notify/base.py`,
`db/notify_repo.py`.

Only when `[notify] channels` is non-empty. Per channel: stored-bucket `top` stories first seen in
the last 48 h, not hidden, not yet sent on that channel (`notifications` table), score desc, ≤ 20.
Quiet hours `22:00–07:00` local hold them (sent after). Discord: webhook via `Fetcher.post_json`,
host allowlist `discord.com`/`discordapp.com`, `allowed_mentions: {parse: []}`, Markdown-escaped
embeds, size limits. Email: stdlib `smtplib` (STARTTLS or implicit TLS), plain text, header
injection stripped. Secrets: `SIDEREAL_DISCORD_WEBHOOK_URL`, `SIDEREAL_SMTP_PASSWORD` from env,
`$CREDENTIALS_DIRECTORY`, or `~/.config/sidereal/env` (refused if group/other readable). Every
error string is `scrub`bed; an httpx log filter redacts POST URLs. A channel error → run
`partial`, never `failed`; unsent stories retry next run.

### 4.8 Retention, unload, finish, run status and stats

- **Retention** (`pipeline/retention.py`): clear `items.content_text` older than 30 days; delete
  dropped/filtered/triaged_out stories older than 90 days (cascade to items, assessments,
  feedback, notifications). Failure → run `partial`.
- **Unload**: triage/assess/digest models get `keep_alive: 0` if the LLM was used, except models
  in `models.never_unload` (pi's coding model).
- **Status**: `ok`; `partial` with `error` = reasons joined by `; ` (sources failed, ollama
  unavailable, deadline reached, digest/weekly digest left, notify failed, retention failed);
  `failed` on any unexpected exception (committed work kept, traceback logged); `skipped` when
  locked. CLI exit: 1 only for `failed`.
- **Stats** (`runs.stats_json`): per-stage counts (`sources`, `items`, `stories`, `prefilter`,
  `triage`, `enrich`, `assess`, `buckets`, `digest`, `week_digest`, `notify`, `retention`, `gate`,
  `recovered_runs`) and `durations_s` (fetch, assess, digest, total). Shown on the Runs page.

## 5. LLM layer

- `llm/ollama.py` `OllamaClient(base_url, *, timeout_s=300, never_unload=())`: the only Ollama
  HTTP client. `chat_json(model, system, user, schema, validator, num_ctx=8192, temperature=0,
  keep_alive="10m", think=False) -> ChatResult`. Uses Ollama's `format` = JSON schema; validates
  with pydantic; on bad JSON/validation re-sends once with a fixed retry line; then
  `LLMOutputInvalid`. Transport/HTTP errors → `LLMUnavailable` (never retried). Also `ps()`,
  `has_model()`, `unload()`, `probe()`.
- `llm/prompts.py`: `load_prompt(name, version="v1")` reads `prompts/<name>.<version>.txt`
  (header `#` lines, system part, `=== USER ===`, user part), `render(t, **values)` (missing →
  KeyError, extra → ValueError), helpers that render focus areas, triage lines, the article block,
  digest lines. All article-derived text is wrapped in `<untrusted_article>` tags with nested tags
  neutralised (`‹`). `$SIDEREAL_PROMPTS_DIR` overrides the folder.
- Prompts: `triage.v1`, `assess.v1`, `day_digest.v1`, `week_digest.v1`. The owner profile is fixed
  text inside the prompts. **Changing a prompt's meaning = new version file** (`assess.v2.txt`)
  and bump the version string in the caller; `assessments.prompt_version` records which one was
  used (rule in `prompts/README.md`).
- Step modules (`triage.py`, `assess.py`, `digest.py`, `week_digest.py`) take already-rendered
  `system`/`user` strings and own the JSON schema + pydantic validator for their reply.
  `assess.strip_urls` is the canonical URL stripper.
- Models: `[models] triage/assess/digest` (all `qwen3.8:27b`), `keep_alive` 10m, `never_unload`.

## 6. Data model

SQLite at `$STATE/sidereal.db`, pragmas in `db/connect.py` (WAL, foreign keys on, busy timeout).
Times are UTC ISO 8601 strings ending `Z`. JSON columns end in `_json`.

| Table | Migration | Purpose |
|-------|-----------|---------|
| `sources` | 0001 | feed config + health (`etag`, `last_ok_at`, `consecutive_failures`, `zero_item_runs`) |
| `focus_areas` | 0001 | key, tier primary/secondary/side, description (prompt text), keywords |
| `runs` | 0001 | trigger, status, `stats_json`, error |
| `stories` | 0001 | title, `day` (local), state, `filter_reason`, `triage_relevance`, `score`, `bucket` (uncapped), `cve_ids_json`, `flags_json` (`kev`, `kev_vendor`, `exploited`, `cvss`) |
| `items` | 0001 | one per source article; UNIQUE(source_id, guid), UNIQUE(canonical_url); `excerpt`, `content_text`, `content_status` |
| `assessments` | 0001 | one per story: rubric, tags, summary, why, `raw_json` (has `focus`), model, prompt_version |
| `day_digests` | 0001 | per day: overview, headline, `story_ids_json` |
| `settings` | 0001 | UI overrides, one row per section (`scoring`, `budget`, `triage`) |
| `users`, `sessions`, `login_attempts` | 0002 | auth (§8) |
| `feedback`, `mutes` | 0003 | votes/read/hide per story (CASCADE); muted sources/keywords |
| `story_search` (FTS5) | 0004 | title, summary, why, tags, excerpt; kept in sync by triggers |
| `notifications` | 0005 | sent log, PK(story_id, channel) |
| `week_digests` | 0006 | per ISO week |
| `schema_version` | `db/migrations.py` | applied migration numbers |

- **Migrations** (`db/migrations.py`): files `db/sql/000N_name.sql`; every file whose number is
  not yet in `schema_version` is applied, each in its own `BEGIN IMMEDIATE` transaction with a
  re-check (safe against concurrent processes). Statements split with `sqlite3.complete_statement`,
  each must end with `;`. `sidereal init`, `run`, `serve` and the CLI user commands migrate.
  Migrations are forward-only; there are no down migrations.
- **Repos** (`db/*_repo.py`): plain functions `f(conn, ...)`, each write its own `with conn:`
  transaction (nested `with conn:` does not give atomicity across calls). Unknown id on write →
  KeyError, on read → None. All SQL lives in `db/` only, `?` parameters only (static rule).
- **Visible story** (UI/API) = has a bucket or is `assess_failed`, and is not hidden.
- Seeding (`db/seed.py`) is insert-only by key: deleting a seeded source/focus area is undone by
  the next `sidereal init` (disable instead).

## 8. Authentication and web security

Layers (outermost first): TrustedHost (`web.allowed_hosts`, bad Host → 400) → write guard
(`api/security.py`) → auth middleware (`auth/middleware.py`) → routes. Security headers on every
response (strict CSP `script-src 'self'`, nosniff, frame deny, referrer policy), `no-store` on
`/api`.

- **Write guard**: POST/PUT/PATCH/DELETE need header `X-Sidereal: 1` and an `Origin` (else
  `Referer`) whose host is in `allowed_hosts` with port `web.port`, or exactly in
  `allowed_origins`. This plus SameSite=Strict is the CSRF defence.
- **Auth** (`[auth] mode = "off"` by default): when `on`, every `/api` path except health, login,
  logout needs a session. Users via CLI only (`sidereal user add`), no default user. Argon2id
  passwords (12–1024 chars), dummy verify for unknown users, session token = 32 random bytes,
  only SHA-256 stored, idle 7 d / absolute 30 d, cookie `sidereal_session` HttpOnly SameSite=Strict
  (`Secure` iff `web.https`). Login rate limit in the DB (5 per user+IP, 20 per IP, 50 per user per
  15 min, reserved atomically). Optional TOTP (stdlib RFC 6238, replay-protected in memory).
  All failures answer the same 401. Log line for fail2ban: `auth: login failed ip=…`.
- **Rule 9 / exposure** (`api/bind.py`): `serve` refuses a non-loopback bind, any
  `trusted_proxies`, or a non-loopback `allowed_hosts` name unless auth is on and an active user
  exists. `doctor` reports the same (`doctor_web.py`).
- Client IP: the peer, or the rightmost untrusted `X-Forwarded-For` hop if the peer is in
  `trusted_proxies` (IPs/CIDRs). uvicorn runs with `proxy_headers=False`.
- LAN/Caddy setup: `deploy/README.md` "LAN deployment", `deploy/Caddyfile.example` (not yet
  validated with `caddy validate`).

## 12. Deployment and operations

- **Install / update**: `./install.sh` from the repo root does everything and is safe to re-run:
  venv + packages (when `pyproject.toml` changed), UI build, `sidereal init`, links
  `~/.local/bin/sidereal` → `.venv/bin/sidereal`, installs the units (checkout path rewritten),
  `daemon-reload`, enables web + both timers, restarts the web app, offers lingering (asks before
  sudo), runs `sidereal doctor`. `./install.sh --uninstall` removes services and the link, keeps
  data. Tests: `tests/test_install_script.py`, `test_install_path_link.py`, `test_install_cli.py`
  (fake `systemctl`/`loginctl`/`sudo`, `--no-build --no-doctor`).

  carry counts, keys, ids and exception types only (no article text or prompts).
- **Manual run**: Runs page "Run now", or `systemctl --user start sidereal-run-manual.service`, or
  `sidereal run` in a shell.
- **Backups/restore**: `$STATE/backups/`; restore steps in `deploy/README.md` (stop units, copy
  file over `sidereal.db`, remove `-wal`/`-shm`, start).
- **Upgrading code**: `git pull`, then `./install.sh` (re-installs packages if needed, rebuilds
  the UI, restarts the web app); migrations apply on the next run/serve.
- **Health**: `sidereal doctor`; `GET /api/health`; Sources page health badges (ok / stale /
  empty / failing / broken; rules in `sources_repo.health`).

## 13. Invariants (never break these)

Condensed from plan §1 / `AGENTS.md` Rules; most are enforced by `tests/test_static_rules.py`.

1. The model never decides placement: score/bucket only from `scoring.py`.
2. Untrusted text is data: plain text at ingest; no HTML rendering in the UI; links only from
   `items.url`, http(s) only (checked in the repo, again at the API edge, again in `safeHref`).
3. Outbound HTTP only in `net/fetch.py` (internet) and `llm/ollama.py` (Ollama), via httpx;
   `socket` only in `net/`; `smtplib` only in `notify/email.py`.
4. Every internet fetch goes through the guard on every hop, with timeouts and a size cap.
5. SQL only in `src/sidereal/db/`, literal/constant SQL with `?` parameters (`# sql-ok:` opt-out
   only for whitelisted identifiers).
6. Times stored UTC `…Z`; a story's day is fixed at first sight in `schedule.tz`.
7. Tests never touch the network or a real Ollama (autouse `no_network` fixture).
8. No secrets in the repo, DB, logs or API responses; no default credentials.
9. No exposed bind without auth on + a user.
10. Runs never overlap (flock).
11. stdlib `logging` to stderr; no `print()` in `src/`.
12. `subprocess` only in `api/routes_runs.py` (fixed argv, no shell).
13. Modules ≤ ~300 lines (Python), ≤ ~200 (React components), soft.
14. One test file per module; new tests in new files.

## 15. Maintenance recipes

**Add a source (same kind)**: Settings page → Sources → Add (URL guard-checked, "Test feed" first),
or add a `[[source]]` to `config/defaults/sources.toml` and run `sidereal init`. Set
`options.article_hosts` to allow enrichment; weight ≥ 1.3 bypasses triage (use with care).

**Add a source kind**: new `sources/<kind>.py` implementing the adapter interface (copy
`cisa_kev.py` for JSON, `rss.py` for feeds), import it in `sources/__init__.py` (each module registers its kind in `base.REGISTRY`), report
`entry_count`, raise `SourceBroken` for error pages; add allowed options to
`sources/validate.clean_options`; record a fixture in `tests/fixtures/feeds/` (+ README) and a test
file `tests/test_<kind>.py`; extend `tests/pipeline_helpers.FeedServer` if seeded. All HTTP via
the passed `fetcher`.

**Add a DB column/table**: new `db/sql/000N_<name>.sql` (next free number, each statement ending
`;`), repo functions in `db/` only, update `tests/test_migrations.py` version lists/table list,
update `doctor` expectations only if needed (it compares to the newest file automatically).

**Add a config key**: field in the right `config.py` section model with default, document it in
`config/sidereal.example.toml`; if it should be UI-editable, add bounds in `overrides.py`.

**Change scoring**: numbers → `[scoring]` (or Settings overrides); formula → `scoring.py` (pure,
`tests/test_scoring.py`), then `sidereal rescore` to re-place existing stories.

**Change a prompt**: copy to `<name>.v2.txt`, edit, switch the loader call's version and the
`prompt_version` string; keep placeholders consistent (`tests/test_prompt_files.py`). Changing the
reply shape means changing the schema + validator in the matching `llm/*.py`.

**Change the LLM model**: `[models]` in `sidereal.toml` or `SIDEREAL_MODELS__ASSESS=…`; make sure
`ollama pull` was done (doctor checks presence). A model that ignores JSON schema output will
produce `assess_failed` stories.

**Add an API route**: new `api/routes_<x>.py` with an `APIRouter`, models in `schemas.py`, SQL in a
repo, include it in `api/app.py`; writes are guarded automatically; then
`.venv/bin/sidereal openapi > web/openapi.json && (cd web && ~/.local/node/bin/npm run gen:api)`.

**Add a UI page**: `web/src/pages/<X>Page.tsx`, route in `routes.tsx`, tab in `App.tsx`, data via a
hook in `api/hooks.ts` using `apiGet`; test in `web/tests/`.

**Change the run schedule**: `deploy/sidereal-run.timer`, `web/src/lib/format.ts` `RUN_HOURS`,
`doctor_systemd.RUN_TIMES`; re-run `./install.sh`.

**Turn on auth / LAN**: `deploy/README.md` "Authentication" and "LAN deployment".

## 16. Known limitations and open owner decisions

- M16 (golden set + `sidereal eval`) and M23 (3-day soak) are not done; they need the owner.
- Non-Microsoft KEV entries can reach TOP at relevance 1 (KEV +12 and exploited +8 stack).
- `azure-updates` (weight 1.3) bypasses triage, so AI/Foundry notices take assess slots.
- Notifications use the stored (uncapped) TOP bucket, so they can include stories a view shows
  under Relevant once `top_cap` is full; search also shows the stored bucket.
- No source provides CVSS, so the CVSS bonus never applies.
- No re-dedupe: stories created before a dedupe change stay split.
- `reassess` is a stub; a changed prompt affects new assessments only.
- Mutes affect only `new` stories; already-placed stories must be hidden.
- TOTP replay memory is per process (a restart forgets it); one uvicorn worker assumed.
- Seed keyword false positives (`entra` → "Entrance", `sentinel` → "SentinelOne").
- The Caddy example has not been run through `caddy validate`.

## 17. Gotchas

- Never `source .venv/bin/activate`; call `.venv/bin/...` (the PATH link exists only after
  `./install.sh`, and never in a pi copy). npm is at `~/.local/node/bin/npm`.
- `install.sh` tests run the real script with fake `systemctl`/`loginctl`/`sudo` on PATH and
  `--no-build --no-doctor`; without those flags it would pip/npm install into the real checkout.
- Each repo write commits itself: you cannot wrap several repo calls in one transaction.
- `import sqlite3` outside `db/` is banned even for type hints: use `sidereal.db.Connection`.
- The static SQL rule flags `+` with an SQL-looking literal even between constants defined in
  another way; split into named module constants.
- Tests with auth off that call `serve`/`doctor` must set
  `SIDEREAL_WEB__ALLOWED_HOSTS='["127.0.0.1", "localhost"]'` (the test config's `testserver` host
  counts as exposure).
- `day` is the local day at first sight; DST days are 23/25 h (`routes_days.day_bounds`).
- feedparser must receive bytes (a str can make it fetch a URL/path).
- trafilatura emits a urllib3 SOCKS `DependencyWarning`; it is filtered.
- The web unit has `ProtectHome=read-only`: the app can write only to the state dir.
- `web/dist`, `.venv`, `node_modules`, `*.db` and secrets are never committed.
- Plan said `Sunday - 14.07.2026`; 14.07.2026 is a Tuesday: labels are computed, not copied.

## 19. Regenerating this TOC

The TOC's "Lines" column is computed from the headings. After editing this file, run:

```
python3 - <<'EOF'
import re, pathlib
p = pathlib.Path("Sidereal_documentation.md")
lines = p.read_text().split("\n")
heads = [(i + 1, len(m.group(1)), m.group(2).strip())
         for i, l in enumerate(lines) if (m := re.match(r"^(#{2,3}) (.+)$", l))]
def rng(title):
    for k, (n, lvl, t) in enumerate(heads):
        if t == title:
            last = len(lines) - (lines[-1] == "")
            end = next((m - 1 for m, l2, _ in heads[k + 1:] if l2 <= lvl), last)
            return f"L{n}–L{end}"
    raise SystemExit(f"no heading: {title}")
out = []
for l in lines:
    m = re.match(r"^\| ([0-9.]+) \| (?:@@)?(.+?)(?:@@ \||\s\|\s*L\d+–L\d+ \|)$", l)
    out.append(f"| {m.group(1)} | {m.group(2)} | {rng(m.group(2))} |" if m else l)
p.write_text("\n".join(out))
EOF
```
